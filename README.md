# AI Agent-Generated Sudoku

This repository contains requirements for a Sudoku web game. It is meant to test how different agent harnesses and large language models handle planning and implementation for a project.

## Current State

This repo currently contains planning artifacts and agent guidance for building the application. The application source code is expected to be generated from the PRD and related instructions.

## Repo Structure

- `plans/`: Contains the Product Requirements Document (PRD) for the Sudoku web game, `SudokuWebGame.prd.md`. The PRD outlines the requirements and specifications for the application. AI agents should be able to create a detailed implementation plan from this document.
- `prompts/`: Contains the prompts used to generate the planning content. These prompts are kept for reference and are not expected to be re-run.
    - `create-prd.prompt.md`: The prompt used to generate `SudokuWebGame.prd.md`. The prompt was run from GitHub Copilot in VS Code using Claude Opus 4.7, then reviewed and revised in a separate VS Code GitHub Copilot session using GPT-5.5.
- `.github/skills/`: Contains useful skills that the PRD anticipates will be used during implementation:
    - `aspire`: Guidance for working with .NET Aspire, including deployment and orchestration.
        - Installed from https://github.com/microsoft/aspire/tree/main/.agents/skills/aspire
    - `frontend-design`: Frontend design principles and best practices for the Sudoku web game UI.
        - Installed from https://github.com/anthropics/skills/tree/main/skills/frontend-design
    - `playwright-cli`: Guidance for using Playwright CLI for end-to-end testing.
        - Installed using the Playwright CLI tool as described at https://playwright.dev/agent-cli/skills
- `.github/copilot-instructions.md`: Starter Copilot instructions for the project, generated by `/init` in Copilot CLI and then reviewed by GPT-5.5 in a VS Code Copilot session.

## Evaluation Criteria

Because this repository is intended as a testbed for AI agents, useful outputs should be evaluated on implementation completeness, adherence to the PRD, local runability, test coverage, UI quality, and appropriate use of the included project guidance and skills.
